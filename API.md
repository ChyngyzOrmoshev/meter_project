# API «ИнфоЭнерго»: приборы и показания

Внешний HTTP API **только для чтения**. Позволяет сторонней системе получать список приборов учёта и их показания из базы АСКУЭ. Изменить или удалить данные через него нельзя, команды на реле он не принимает.

- Базовый адрес: `http://192.168.144.145:8000`
- Версия: `v1` (префикс `/api/v1/`)
- Формат ответа: JSON, UTF-8
- Метод: только `GET` (на другие методы ответ `405`)

## Авторизация

Каждый запрос должен содержать заголовок:

```
Authorization: Bearer <токен>
```

Токен выдаёт администратор АСКУЭ командой на сервере:

```bash
docker exec meters_django python manage.py api_token create "Название организации"   # выдать (ключ показывается один раз)
docker exec meters_django python manage.py api_token list                             # список и время последнего запроса
docker exec meters_django python manage.py api_token revoke <id>                      # отозвать
```

В базе хранится только хеш ключа, восстановить потерянный ключ нельзя: нужно выдать новый и отозвать старый. Один токен на одну организацию или систему, чтобы можно было отозвать отдельно.

Ошибки авторизации: `401` с телом `{"error": "..."}` (нет заголовка, неверный или отозванный токен).

## Общие правила

- **Время** хранится и отдаётся по местному времени сервера, без часового пояса: `2026-11-20T12:00:00`.
- **Значения показаний** (`value`) — строки с 8 знаками после точки, чтобы не терять точность: `"100.50000000"`. В числа преобразуйте на своей стороне (`Decimal`).
- **Направление** (`direction`): `aplus` — активная энергия, потребление (A+), `aminus` — отдача (A−).
- **Серийный номер** — строка, точное совпадение (с ведущими нулями, если они есть в базе). Для нескольких приборов номера передаются через запятую, не больше 100 за запрос.
- **Постраничность:** `page` (с 1) и `page_size`. В ответе `has_next` показывает, есть ли следующая страница; общее число записей не считается (таблица показаний очень большая).
- **Ошибки** возвращаются как `{"error": "текст"}` со статусом `400` (неверные параметры), `401`, `404`, `405`.

## Приборы

### `GET /api/v1/devices/`

| Параметр | Описание |
|---|---|
| `serial` | один или несколько серийных номеров через запятую |
| `region` | точное название района, например `ЖПЭС`, `03 Сузак` |
| `status` | `active`, `repair`, `inactive`, `temporary_off` |
| `page`, `page_size` | по умолчанию 1 и 100, максимум `page_size` 1000 |

Ответ:

```json
{
  "items": [
    {
      "serial_number": "11848001",
      "model": "P34S02",
      "status": "active",
      "category": "commercial",
      "phase": 3,
      "nominal_current": "5(100) A",
      "region": "03 Сузак",
      "substation": "ПС Сузак",
      "feeder": "Ф-5",
      "tp": "ТП-12",
      "tt_ratio": null,
      "tn_ratio": null
    }
  ],
  "page": 1,
  "page_size": 100,
  "has_next": true
}
```

Поля, которых нет в базе, приходят как `null`.

### `GET /api/v1/devices/<серийный_номер>/`

Один прибор в том же формате, без обёртки `items`. Если прибора нет — `404`.

## Показания

### `GET /api/v1/readings/`

Показания за период. Параметр `serial` обязателен.

| Параметр | Описание |
|---|---|
| `serial` | обязательный; один или несколько номеров через запятую (до 100) |
| `date_from` | начало периода: `YYYY-MM-DD` или `YYYY-MM-DD HH:MM:SS`. По умолчанию сутки до `date_to` |
| `date_to` | конец периода. Если указана только дата, включается весь этот день до 23:59:59. По умолчанию текущий момент |
| `direction` | `aplus` или `aminus`; без параметра приходят оба |
| `page`, `page_size` | по умолчанию 1 и 500, максимум `page_size` 5000 |

Ограничения: период не больше 92 дней, `date_from` не позже `date_to`.

Записи отсортированы по прибору, времени и направлению.

Пример:

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://192.168.144.145:8000/api/v1/readings/?serial=11848001&date_from=2026-11-20&date_to=2026-11-20&direction=aplus"
```

```json
{
  "items": [
    {
      "serial_number": "11848001",
      "timestamp": "2026-11-20T12:00:00",
      "direction": "aplus",
      "value": "100.50000000",
      "notes": null
    }
  ],
  "page": 1,
  "page_size": 500,
  "has_next": false,
  "date_from": "2026-11-20 00:00:00",
  "date_to": "2026-11-20 23:59:59",
  "not_found": []
}
```

`not_found` — переданные номера, которых нет в базе. Это не ошибка: по найденным приборам данные приходят.

`notes` — источник записи (какой робот или ручной ввод её создал), может быть `null`.

### `GET /api/v1/readings/latest/`

Последнее показание по каждому направлению для перечисленных приборов.

| Параметр | Описание |
|---|---|
| `serial` | обязательный; номера через запятую (до 100) |

```json
{
  "items": [
    {"serial_number": "11848001", "timestamp": "2026-11-23T15:30:00", "direction": "aplus", "value": "4812.30000000", "notes": null}
  ],
  "not_found": []
}
```

Если у прибора нет показаний по направлению, записи для него в `items` нет.

## Пример на Python

```python
import requests
from decimal import Decimal

BASE = "http://192.168.144.145:8000/api/v1"
HEADERS = {"Authorization": "Bearer ask_..."}

def readings(serial, date_from, date_to):
    page = 1
    while True:
        r = requests.get(f"{BASE}/readings/", headers=HEADERS, timeout=60, params={
            "serial": serial, "date_from": date_from, "date_to": date_to,
            "page": page, "page_size": 5000,
        })
        r.raise_for_status()
        data = r.json()
        for item in data["items"]:
            yield item["timestamp"], item["direction"], Decimal(item["value"])
        if not data["has_next"]:
            return
        page += 1

for ts, direction, value in readings("11848001", "2026-11-01", "2026-11-23"):
    print(ts, direction, value)
```

## Рекомендации по нагрузке

- Показания пополняются роботами раз в 30 минут (часть источников — два раза в сутки), чаще опрашивать API нет смысла.
- Забирайте данные по сериям приборов и коротким периодам (сутки, неделя), а не всю историю одним запросом.
- Для текущих значений используйте `/readings/latest/`, он быстрее, чем выборка за период.
